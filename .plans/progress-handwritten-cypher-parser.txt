TASK-018 (semantic analysis) - ANALYSIS DONE, NOTHING IMPLEMENTED
  Expected compile-time errors in the TCK (scenario definitions; outlines multiply):
    UnexpectedSyntax 17 | VariableAlreadyBound 19 | UndefinedVariable 18 |
    VariableTypeConflict 11 | InvalidArgumentType 25 (+2 TypeError) |
    AmbiguousAggregationExpression 6 | IntegerOverflow 6 | NoSingleRelationshipType 5 |
    InvalidNumberLiteral 4 | InvalidAggregation 5 | NonConstantExpression 4 |
    NegativeIntegerArgument 4 | InvalidParameterUse 4 | InvalidNumberOfArguments 4 |
    InvalidClauseComposition 3 | RequiresDirectedRelationship 2 |
    InvalidRelationshipPattern 2 | InvalidDelete 2 | DifferentColumnsInUnion 2 |
    CreatingVarLength 2 | ColumnNameConflict 2 | ProcedureNotFound 2 |
    one each: UnknownFunction, RelationshipUniquenessViolation, NoVariablesInScope,
    NoExpressionAlias, NestedAggregation, InvalidUnicodeLiteral,
    InvalidUnicodeCharacter, InvalidArgumentPassingMode, FloatingPointOverflow,
    MissingParameter.
  Runtime / any-time expectations (DeletedEntityAccess, NumberOutOfRange,
  InvalidArgumentValue, MergeReadOwnWrites, ...) are NOT part of 018.

  Suggested design
    * New package cypher/analyze (imports cypher/syntax only) with
      Error{Class, Code, Pos, Msg}; Code constants use the TCK names.
    * cypher.Parse = syntax.Parse -> analyze -> lower. Check that graphlite's error
      wrapping keeps %w so the harness can use errors.As.
    * Plain *syntax.SyntaxError maps to class SyntaxError / code UnexpectedSyntax.
    * Harness: for "at compile time" require class AND code to match; keep
      runtime / any-time lenient.
  Sub-steps (each shippable): A plumbing + strict harness; B scope analysis;
  C aggregation rules; D literal/lexical codes; E clause/pattern rules; F static
  type inference (largest group, ~120 expanded cases: NOT/AND/OR/XOR on non-booleans,
  IN on non-list, properties()/length()/type()/labels()/size() argument kinds,
  property access on non-maps, quantifier element mismatch, DELETE 1+1, bare
  pattern as WHERE predicate) plus UnknownFunction (needs a function registry).
  Procedure codes belong to task-026.

  Notes found while reading the scenarios
    * Several codes are already half-covered by the parser: UNION mix is a syntax
      error today but has no code; CREATE ()-[:FOO*2]->() parses fine and must be
      rejected as CreatingVarLength; "[:LIKES..]" and "*-2" need
      InvalidRelationshipPattern; IntegerOverflow is currently reported as a
      plain syntax error ("integer literal ... is too large").
    * ORDER BY scoping after WITH / RETURN DISTINCT is the trickiest scope rule
      (UndefinedVariable cases in WithOrderBy*/ReturnOrderBy*).
    * SKIP/LIMIT: literal negative -> NegativeIntegerArgument, float ->
      InvalidArgumentType, non-constant -> NonConstantExpression (compile time);
      the same checks on parameters are RUNTIME and out of scope.
